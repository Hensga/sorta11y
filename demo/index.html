sorta11y

Barrierefreie, abhängigkeitsfreie Vanilla-JS-Sortierliste — Tastatur, Maus/Touch und Screenreader. Kein Framework, kein Build-Step.

Zero Dependencies · WCAG 2.2 · Tastatur + Touch · Screenreader-Ansagen

Alle Beispiele sind live. Per Tastatur: Tab auf einen Griff, Leertaste aufnehmen, ↑/↓ bewegen, Leertaste ablegen, Esc abbrechen — oder mit Maus/Touch ziehen. Schalte die Optionen um und beobachte, wie sich Verhalten und Code ändern.

Grundliste

Eine server-gerenderte <ul>, die sorta11y nur enhanced. Jeder Eintrag ist ein Tab-Stopp. Neben den eingebauten Zustands-Klassen kann sorta11y beim Greifen eine eigene Klasse ans Item hängen: grabbedClass beim Tastatur-Griff (Tab auf eine Zeile, dann Space), draggingClass beim Maus- oder Touch-Ziehen. Beide sind additiv — die interne CSS (z-index-Lift) bleibt erhalten. Zur Demo signalisiert die eigene Klasse den Zustand über Farbe und ein Text-Label — Farbe allein wäre nach WCAG 1.4.1 zu wenig. Schalte sie zu und vergleiche. Mit clickToGrab (Standard: an) legst du fest, ob ein Klick ein Element aufnimmt wie die Leertaste — aus bedeutet: die Maus kann nur ziehen.

Optionen

    Drag-Handle

    Mit einem echten <button>-Griff wird der Griff zum Steuerelement (mit aria-pressed) — der empfohlene Weg für vollen Screenreader-Support. Ohne Griff ist die ganze Zeile das Greif-Ziel.

    Griff

      Aus einem <select multiple>

      Sorta11y.fromSelect() baut die barrierefreie Liste aus einem <select> (das Spiegelbild von mirrorToSelect), versteckt das Select und spiegelt jede Umsortierung zurück — ein normaler Formular-Submit trägt die Reihenfolge. Wähle die Griff-Seite: rechts ist am Touchscreen besser per Daumen erreichbar.

      Griff-Seite Griff

      Was der Screenreader hört

      sorta11y spricht jede Änderung über eine ARIA-Live-Region aus — sonst unsichtbar. Hier wird sie sichtbar gespiegelt: nimm einen Eintrag auf und bewege ihn, dann erscheint die Ansage im Kasten.
